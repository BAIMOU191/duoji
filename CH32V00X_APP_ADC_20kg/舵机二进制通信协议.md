# 舵机二进制通信协议

本文说明 `CH32V00X_APP_ADC_20kg` 的应用层二进制串口协议。固件同时保留旧 ASCII 协议，并继续支持原有 IAP 升级协议。

## 1. 帧格式

```text
AA 66 | ID | CMD | LEN | DATA | CRC8 | 66 AA
```

| 字段 | 长度 | 说明 |
|---|---:|---|
| 帧头 | 2字节 | 固定为 `AA 66` |
| ID | 1字节 | 舵机地址 `0~254`，`255` 为广播 |
| CMD | 1字节 | 命令字 |
| LEN | 1字节 | DATA 的字节数，最大32 |
| DATA | LEN字节 | 命令参数或返回数据 |
| CRC8 | 1字节 | 校验 `ID + CMD + LEN + DATA` |
| 帧尾 | 2字节 | 固定为 `66 AA` |

一帧的总长度为 `8 + LEN` 字节。所有 `u16`、`i16`、`u32` 数据都采用小端顺序。

CRC 使用 CRC-8/ATM：多项式 `0x07`、初始值 `0x00`、结果异或 `0x00`，不反射输入和输出。

## 2. 应答规则

应答命令字为请求命令字与 `0x80` 按位或。应答 DATA 的第一个字节固定为状态码，后面才是返回值。

| 状态码 | 含义 |
|---:|---|
| `00` | 成功 |
| `01` | 不支持的命令 |
| `02` | DATA 长度错误 |
| `03` | 参数值错误或参数ID不存在 |
| `04` | 当前状态不允许执行 |
| `05` | 操作执行失败 |

单播请求均应答。广播地址 `FF` 可以执行写入或动作命令，但设备不应答，以免多台设备争抢总线。CRC错误、帧尾错误、地址不匹配的帧直接丢弃。

## 3. 命令表

### 设备配置

| CMD | 功能 | 请求 DATA | 成功应答数据（状态码之后） |
|---:|---|---|---|
| `01` | 查询固件版本 | 无 | `u8 major, u8 minor, u8 patch` |
| `02` | 查询ID | 无 | `u8 id` |
| `03` | 设置ID | `u8 id` | 无 |
| `04` | 查询波特率 | 无 | `u8 baud_code, u32 baudrate` |
| `05` | 设置波特率 | `u8 baud_code` | 无 |
| `06` | 恢复默认 | `u8 scope` | 无 |

波特率档位与旧协议一致：`1~8` 对应 `9600、19200、38400、57600、115200、128000、256000、1000000`。设置波特率时，应答使用旧波特率发完，随后设备切换到新波特率。

恢复默认的 `scope=0` 表示保留ID，`scope=1` 表示包括ID在内全部恢复。

### 运动控制

| CMD | 功能 | 请求 DATA |
|---:|---|---|
| `10` | 位置/时间运动 | `u16 target_pwm_us, u16 time_ms` |
| `11` | 定圈运动 | `u16 target_pwm_us, u8 turns, u16 turn_time_ms` |
| `12` | 暂停 | 无 |
| `13` | 继续 | 无 |
| `14` | 停止 | 无 |

目标脉宽范围为 `500~2500us`，圈数范围为 `0~9`。

### 电机与舵机设置

| CMD | 功能 | 请求 DATA | 成功应答数据 |
|---:|---|---|---|
| `20` | 卸力 | `u8 level` | 无 |
| `21` | 恢复扭矩 | 无 | 无 |
| `22` | 查询模式 | 无 | `u8 mode` |
| `23` | 设置模式 | `u8 mode` | 无 |
| `24` | 查询扭矩上限 | 无 | `u8 percent` |
| `25` | 设置扭矩上限 | `u8 percent` | 无 |
| `26` | 查询上电动作 | 无 | `u8 mode` |
| `27` | 设置上电动作 | `u8 mode` | 无 |
| `28` | 保存当前位置为上电位置 | 无 | 无 |

卸力级别 `0` 为低阻力，`1` 为高阻力。

### 标定

| CMD | 功能 | 请求 DATA |
|---:|---|---|
| `30` | 中位校正 | 无 |
| `31` | 零点校正 | 无 |
| `32` | 捕获自定义行程端点 | `u8 endpoint` |
| `33` | 捕获脉宽边界 | `u8 endpoint` |

`endpoint=0` 表示最小端，`endpoint=1` 表示最大端。

### 状态查询

| CMD | 功能 | 成功应答数据（状态码之后） |
|---:|---|---|
| `40` | 查询当前位置 | `u16 position_pwm_us` |
| `41` | 查询运行数据 | `u16 position_pwm_us, i16 temperature_dC, u16 voltage_cV` |
| `42` | 查询电源数据 | `u16 current_mA, u16 voltage_cV` |

`temperature_dC` 的单位是0.1摄氏度，`voltage_cV` 的单位是0.01伏。

### 轨迹参数

| CMD | 功能 | 请求 DATA | 成功应答数据 |
|---:|---|---|---|
| `50` | 读取单个参数 | `u8 parameter_id` | `u8 parameter_id, u32 value` |
| `51` | 修改单个参数 | `u8 parameter_id, u32 value` | 无 |
| `52` | 读取全部参数 | 无 | 依次返回5个 `u32` |

全部参数的返回顺序固定为 `VMAX、AMAX、DMAX、JMAX、MOVE_MIN`。

| 参数ID | 参数 | 单位 | 默认值 | 范围 |
|---:|---|---|---:|---|
| `01` | VMAX | 度/秒 | 265 | `1~本机硬件上限` |
| `02` | AMAX | 度/秒² | 5000 | `50~100000` |
| `03` | DMAX | 度/秒² | 4000 | `0`或`50~100000` |
| `04` | JMAX | 度/秒³ | 2000000 | `500~2000000` |
| `05` | MOVE_MIN | ms | 60 | `0~200` |

`DMAX=0` 表示跟随 AMAX；`MOVE_MIN=0` 表示关闭小位移时间限制。修改成功后立即用于下一次轨迹规划，并异步保存到 Flash。

## 4. 示例

查询 ID=0 舵机的固件版本：

```text
AA 66 00 01 00 15 66 AA
```

读取全部轨迹参数：

```text
AA 66 00 52 00 26 66 AA
```

把 VMAX 设置为265。`265 = 0x00000109`，小端数据为 `09 01 00 00`：

```text
AA 66 00 51 05 01 09 01 00 00 6B 66 AA
```

成功应答如下，其中 `D1 = 51 | 80`、DATA中的 `00` 为成功状态：

```text
AA 66 00 D1 01 00 51 66 AA
```

## 5. 与旧协议、IAP共存

固件根据帧头并行识别三类数据：

```text
#      旧ASCII舵机协议
AA 66  本文描述的二进制应用协议
AA 55  IAP升级协议
```

旧 ASCII 指令仍可继续使用，但新增轨迹参数仅通过二进制协议读写。
