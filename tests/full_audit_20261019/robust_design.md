## 统一整改设计：职责、约束与必须拒绝的简单修法

以下S1～S6是对原编号问题的归并方案。**优先在现有Servo、Protect、Config、Planner、Controller及调度边界修正，不新增通用状态引擎、事件总线、全局恢复管理器或按kg分支。**局部修复本身并不等于“打补丁”；关键在于它是否恢复一个清晰的模块约束，并能通过关联路径的回归。

### S1. 扭矩意图和保护原因分离；实际驱动只有一个写入者

解决1、3，并约束恢复默认、失能、故障和自动恢复的组合。

- 用户请求（正常/释放/阻尼）由Servo拥有；保护只拥有故障/禁止原因和输出上限；H桥实际模式仍由Servo统一决定。保护不再调用会修改用户请求的公共ULK/ULR函数，因而不需要一个容易过期的released布尔值。
- 普通运行下，禁止原因存在则不允许正常出力；无禁止原因时按用户请求执行。请求和实际状态各自有明确读回，不强求故障期间两者相等，也不允许无故障时无解释地不一致。
- 明确兼容现有“新运动命令可恢复扭矩、故障恢复后不继续旧动作”的语义。故障时被拒绝的ULR/运动命令没有隐藏副作用；用户ULK/阻尼可以更新请求。
- 推荐恢复默认提交正常请求、取消旧目标、允许时就地保持；不自动回中，不清除尚未解除的故障。故障与恢复默认同时到来时，故障优先；随后用户再ULK，最后的用户请求优先保留。需要回中时另走正常规划。

职责流可由现有A_Tasks串联：采样/运动快照→Protect给决策→Servo合成实际输出。不要让Protect和Servo互相调用对方的状态恢复函数。只读运动采样与写入扭矩状态要区别对待，不能为消除一个布尔值再复制整套控制状态。

**必须验收：**六种恢复入口×正常/释放/阻尼×无故障/单故障/多故障；故障依次解除、故障期间ULK/ULR/新运动、同批串口帧顺序、恢复后的旧目标取消、阻尼比例保持。禁止为了保持输出“连续”而推迟硬故障卸力。

### S2. 参数共用校验和提交路径，历史状态按所属模块处理

解决2、4、6、9及Flash/SRAM不同入口的副作用差异。

Flash影子与SRAM参数分开是必要功能，不能简单合并。建议协议只产生“参数值/存储范围/动作”，统一校验候选值与关联字段，提交后由所属模块处理变化：

| 数据或状态 | 所属模块 | 变更规则 |
|---|---|---|
| 持久化影子、dirty、保存版本 | Config | Flash写法更新影子；SRAM写法不改持久化影子 |
| 用户请求参数、动作意图 | 应用编排/Servo | 各协议入口语义相同；整组提交失败不得先做一半副作用 |
| 活动V/A/D/J与待提交限值 | Planner | 小型运动参数快照；按S3明确切换条件 |
| 有效保持窗口/增益、积分、过渡补偿 | Controller | 按S4控制过渡；协议层不直接改私有状态 |
| 过流/过温/堵转计时、故障与限流状态 | Protect | 无关参数不重置；关联阈值改变遵守可解释的历史规则 |
| 母线换算是否就绪、已生效比例 | Servo/传感器质量接口 | 第一份有效电压建立比例，不依赖非零输出 |

不必复制整个Config做三四份“当前状态”，只对必须一致切换的字段保留小快照/版本。现有任务是协作式，问题主要是语义一致，而非每个字段都需要加锁；若以后并发模型变化，再单独处理原子性。

保护更新必须满足：改变扭矩不重置高温时长；无关参数不重置过流时长；改变过流阈值不改温度计时；已有故障不能因普通参数提交而直接清除。对于提高阈值后旧历史是否仍有效，若没有足够历史证据就不能冒称已满足新阈值；相关检测器可以按文档规则重新确认，独立硬件限流仍有效。

电压校验必须同时用于协议、恢复默认的候选值及开机修复。第一份有效母线电压的建立属于就绪状态转换，不应为此复制一套特殊“0 V恢复控制器”。恢复后的运动是否重发/保留也应使用正常动作语义。

**必须验收：**Flash/SRAM/重载/默认各路径交叉；同值写入；上下限修改顺序；边界单位和舍入；低于新阈值但高于旧阈值的传感器历史；阈值改严；已有故障；未建立母线比例时受理命令的ACK与目标状态；待生效值与实际生效值的读回语义。

### S3. 规划器约束必须对输出离散序列成立，不靠末端夹值兜底

解决7、8，保留同一套跨型号算法。

规划器的正常连续推进至少要对同一活动约束定义：`|Δa| <= J·Δt + εa`、速度/加速度边界、位置与速度/加速度的一致性、有限时间完成和终点误差。εa若非0，必须由固定点表示、段长和舍入推导；不能先观察最大误差再加一个“刚好过测试”的容差。边界硬夹、紧急停止与安全禁止应单独标记，不能和正常连续轨迹混算成“任何时刻都严格连续”。

一拍接管必须执行；该局部修复恢复的是规划器内部加速度连续性，不增加跨模块耦合。但隔离试验证明它只消除主要突变，还需要覆盖普通S曲线定点系数、接管余数和段缝。独立裁剪输出acc会破坏前馈与参考位置的关系，不是充分方案。

活动中降低限值的合同建议为：新值可被接受为待提交值；若当前状态不能满足它，则旧活动约束执行连续减速/停止，提交新约束后再执行最新目标。接管本身必须可被新目标更新但不可被无穷重启；可写软限值与硬保护限额分开。若产品不愿提供待提交/过渡语义，安全的较小实现是对不兼容的活动中修改返回明确状态错误，让上位机先停稳；不要表面ACK成功却无限期静默不生效。

只等待a=0不充分：速度仍可能高于新V。更不能无条件将旧状态按新限值瞬间夹为0。在行程边界附近，无法同时满足连续性与不越界时，应优先保持硬边界并返回不可行/安全停止状态，不能隐藏为普通成功轨迹。

**必须验收：**正反方向；A≠D；最小/最大平滑；最小/最大V/A/D；n=0/1/2/199/200及理论n>200；每1/4/7/20 ms重规划；正在减速时改反向目标；到边界时降限；反复热改；暂停/继续；T=0/5000/65535；饱和冻结与解除。对输出序列、完成时间与终点共同断言，不能只检查最大acc。

### S4. 控制器区分负载记忆、短时接管和硬限额

解决9、10、11，澄清12、13。

保留Controller对积分和闭环模式的唯一所有权。负载积分是长期状态，状态过渡带来的暂态反馈差额不应无条件写进去。若使用过渡补偿，至少规定幅值、退出时间/条件、反向指令的处理、连续重触发的收敛以及饱和时的处理；它只解决正常切换的输出过渡，不能代替闭环稳定性分析。

不推荐对最终PWM简单加一个统一斜率限制：它会增加闭环相位滞后，也可能延迟制动、卸力和限流。若在正常控制律内有受控的有效参数/输出过渡，其实际输出仍必须服从当前硬上限；改变了实际执行量时，观测器与抗饱和处理必须以实际执行量为准。

对已有积分要区分临时可用电压下降、用户长期降扭矩、故障和用户卸力：临时下降后保留一部分托举记忆可能合理，永久降额后让旧积分突然全部回归则可能不合理。不能统一“限幅就清I”，也不能无限记住任何已不可实现的积分。抗饱和方式和释放速度必须通过负载工况验证。

短暂无效反馈时，冻结正常状态/积分迁移，但最新硬限额和故障处理照常执行；是否继续模型预测有明确时限。不要把无效采样当静止证据触发起转、到位或积分接管。

默认软保持应保留到产品要求改变为止。增加当前在位判断时，只是遥测语义补全，不自动强迫进入硬定位；持续硬定位若需要，应与堵转监督一起设计，避免反复重捕获、积分和堵转互相重置。极低速摩擦策略仍是待台架验证候选。

**必须验收：**MOVE/SETTLE/HOLD两两相关转换；窗口扩大/缩小与P/I热改；噪声和1～4拍缺采样；托举量接近/超过半电压积分预算；正负负载；临时限流反复进出；新目标反向；输出硬上限突降；急停/释放。验收同时观察电压阶跃、到位时间、负载掉落、噪声驱动和积分回归，不能只用“第一拍相等”判断无扰。

### S5. 进度失败、柔顺保持和传感器恢复分开监督

解决5、14，并避免为12加入的定位策略与保护冲突。

Protect监督动作进度，Controller负责把动作收敛；不要由Protect写控制器积分。一个动作在MOVE或SETTLE未完成且存在足够可辨识的运动需求时，才累计无进展证据；主动暂停、无效反馈、极小参考步进和HOLD柔顺偏移不能共享同一个固定超时。

进度应使用足够的观察窗口累计位移与误差趋势，窗口内参考净位移在反复换向时可能相互抵消，必要时区分累计路程与净位移。受限输出与实际输出也应区分：只看“饱和标志”会漏掉低速、不饱和但仍卡住的情况。阈值必须结合本型号噪声/最小可靠位移，不能简单把默认128厘度换成一个更小的常数。

动作完成/取消事件的记录必须保留原请求目标与结果原因，避免堵转后把目标改成当前位置，随即用误差0把它报告成成功到位。此处可以增加动作结果诊断，不必重写规划器。

传感器恢复只使用真实可观测的质量与历史；死区与断线都可能表现为同一个低电平，不能承诺仅靠软件识别。若允许受限搜索，时间、功率和退出条件必须独立于新运动命令，不能每来一条命令就重新获得完整搜索预算。

**必须验收：**快速/慢速、大小动作锁轴；T拉长；饱和冻结；SETTLE失速；重载但持续前进；外力柔顺保持；参考往复抵消；ADC未就绪/DMA失效/悬空特征/端点死区；搜索两方向/换向/恢复/超时；期间新命令、参数变化和保护触发。传感器异常时不应把“无反馈”归因成正常堵转并继续加力。

### S6. 持久化保证与1 ms实时保证分开兑现

解决15并收紧首轮Flash结论。

参数已接受、运行参数已提交和Flash已保存是不同事实。已有协议OK若继续表示“已接受”，应保留兼容语义并另提供保存完成/失败或代数查询；不能偷偷把旧ACK改成需要等待任意长Flash操作的阻塞ACK。

保存任务可合并变化，但需明确最大待保存时长及掉电前未保存风险。仅“等运动结束”在持续目标流/持续保持负载时可能永远不保存，并不鲁棒；应定义允许保存的受控停顿，或选择硬件支持的可并行存储方案，并让用户与上位机知道实际保证。

固定1 ms算法不能靠调度器补跑若干次旧采样恢复真实经过的时间。确有超期时，应记录并按允许的短缺样策略/安全重建处理；增加真实时间诊断不等于已把观测器和轨迹都改成可变dt。

双页CRC机制本次未发现逻辑性保存丢失；顺序字节模型的3075次通过应保留为回归证据，不包装成所有真实Flash故障都绝对安全。硬件断电注入、写入最低电压和任意撕裂方式需要另测；也没有依据为了本次问题强行增加一层日志系统。

**必须验收：**连续写同值/不同值、失败重试、保存中改参、连续目标流、保持带载、保存期间串口满速输入、擦写最坏控制间隔、断电前尚未完成ACK/保存、两页受损。所有时序结论需标明主机注入或目标硬件测量，不能混用。

### 方案成熟度与本次边界

| 项目 | 本次完成 | 尚不能宣称完成 |
|---|---|---|
| 问题真实性 | 原代码复现、公开接口可达性、正常对照、三机一致性 | 实机发生频度与所有机械后果 |
| 一拍接管候选 | 隔离试验排除了“一行即可严格修完”的结论 | 严格jerk上限、全部离散边界和候选目标编译/台架验收 |
| 扭矩/参数/保护整改 | 所有权、不变量、路径一致性、反例与组合验收设计 | 改后实现已通过闭环回归 |
| HOLD与低速策略 | 区分需求与模型限制，60 s反例复核 | 柔顺/硬定位两类需求同时自动满足、低速实机保证 |
| Flash与实时性 | 顺序断电模型回归、阻塞结构分析 | 硬件擦写最坏时间、任意掉电与全工况1 ms保证 |

建议实施时按S1/S2→S3→S4/S5→S6的小步变更回归，先冻结接口语义与硬约束，再写实现。每一步必须保留三型号同一算法与差异参数，不把单个波形调好视为全局验收。
