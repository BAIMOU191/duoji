# 恢复默认与 IAP 升级核对（2026-10-16）

已同步至 ADC 15kg、ADC 20kg、ADC 20kg-double、ADC 30kg、IIC 20kg，共 5 个应用工程。

| 明文 | 二进制命令 | 系统动作参数 | 执行结果 |
|---|---|---|---|
| `#IIIPCLE0!` | CMD `07`，空 DATA | CMD `03`，DATA `8C 02` | 仅保留当前 ID，其他全部参数恢复固件默认值 |
| `#IIIPCLE!` | CMD `08`，空 DATA | CMD `03`，DATA `8C 03` | 全部参数恢复固件默认值，包括 ID=0 |

两组命令都将波特率恢复为档位 5（115200），同时恢复 Flash 配置和 SRAM 运行参数（包括正常扭矩模式、阻尼默认值）。参数在后台保存。应答使用恢复后的 ID、原通信波特率，发送完毕后切换到 115200。`III` 是执行前的设备 ID（000 只是 ID=0 的示例）。

根因：此前 CLE0/CLE、CMD07/08 和系统动作 2/3 被合并到同一个保留 ID 与波特率的默认恢复函数。现已显式区分仅保留 ID 和全部恢复，并为每个入口登记延迟波特率切换。

## IAP 核对结论

IAP 的默认恢复独立于用户恢复指令：Boot 在擦除前将有效参数页中的 ID、波特率及兼容性核对所需硬件身份记录到升级状态页；随后擦除 APP、两个参数页和硬件信息页。CRC 和机型校验通过后，重启到新 APP，由新固件建立默认参数和硬件能力，只恢复升级前的 ID 与波特率。

重新刷入相同镜像也会清除旧用户参数。正常的同一固件断电重启则沿用已保存参数；固件镜像变化时，即使版本号不变，也会按新固件默认值重建参数并保留有效 ID/波特率。Bootloader 代码及布局没有改动。

另修复了立即进入升级的边界：APP 在升级应答发完后先确认待保存参数写入成功，才复位到 Boot，避免刚修改的 ID/波特率尚未保存而被旧值替代；保存失败则重试，不提前复位。
