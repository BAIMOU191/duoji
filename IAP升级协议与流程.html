舵机 IAP 升级协议与流程

本文给出串口参数、帧格式、CRC、命令字段、固件文件处理、升级状态机、超时重试、掉电恢复和完整报文示例。所有多字节整数均为小端序。

固定升级行为：升级只保留有效参数页中的舵机ID和波特率档位；APP、全部用户参数和硬件信息均被清除。新APP首次启动后使用保留的ID/波特率，其余参数采用新固件默认值。

一、接口与适用范围

项目APP阶段Boot阶段
物理接口单线半双工 UART，PC0，8数据位、无校验、1停止位
波特率舵机当前配置的波特率固定115200 bps
寻址命令数据第1字节为舵机ID；查询命令允许ID 255无ID字段，进入Boot后默认总线上只有目标设备
最大DATA长度8字节260字节
字节序所有16位、32位整数和CRC均低字节在前
收发方式一问一答。主机发送完成后切换为接收，收到对应应答或超时后再发送下一帧

波特率档位：1=9600、2=19200、3=38400、4=57600、5=115200、6=128000、7=256000、8=1000000。升级成功后APP恢复到升级前保留的档位；若升级前A/B参数页均无效且没有有效IAP快照，则新APP采用代码默认值：ID 0、档位5。

总线要求：建议升级时只连接一台舵机。Boot帧不含ID，多台设备同时停在Boot会同时应答并同时写入。广播查询ID 255也只能在单机连接时使用。
ID 255限制：ID 255只允许用于 CMD=20 查询实际ID。进入升级及升级脚本的 --id 参数必须使用0～254，不能使用广播ID 255。

二、通用帧格式

偏移字段长度说明
0帧头2固定 AA 55
2CMD1请求命令；应答为请求命令按位或 80
3LEN2DATA长度，uint16小端序；不包含CRC和帧尾
5DATALEN请求参数；应答DATA的第1字节固定为状态码

整帧长度为 11 + LEN 字节。协议没有转义字符，DATA中允许出现帧头或帧尾字节，接收端必须以LEN确定帧边界。

def make_frame(cmd: int, data: bytes = b"") -> bytes:
    import struct, zlib
    body = bytes([cmd]) + struct.pack("<H", len(data)) + data
    crc = zlib.crc32(body) & 0xFFFFFFFF
    return b"\xAA\x55" + body + struct.pack("<I", crc) + b"\x55\xAA"

注意：CRC不包含帧头和帧尾；应答帧计算CRC时必须包含应答CMD、应答LEN以及状态码。

四、APP阶段命令

APP阶段使用舵机当前波特率。错误ID、错误CRC、错误长度和未知命令均静默，不返回错误帧。

4.1 查询设备 CMD=20

用于确认目标ID、当前硬件身份和当前固件版本。

方向LENDATA偏移字段说明
请求10ID0～254为指定舵机；255为单机广播查询
成功应答90STATUS固定0
1实际ID设备当前ID
2～5硬件身份舵机类型、硬件版本、电压型号、扭矩型号
6～8固件版本主版本、次版本、修订版本

硬件信息页无效时，4字节硬件身份返回 FF FF FF FF。硬件版本以0.1版为单位，电压型号以V为单位，扭矩型号以kg·cm为单位。

4.2 进入升级 CMD=21

方向LENDATA偏移字段说明
请求80ID必须等于本机ID，不允许255
1～4当前硬件身份必须原样复制查询应答DATA[2～5]
5～7当前固件版本必须原样复制查询应答DATA[6～8]
成功应答10STATUS=0应答发送完成后，设备软件复位进入Boot
关键点：进入升级命令携带的是“查询到的当前设备信息”，不是目标固件的信息。7字节不一致时返回状态2，设备不会复位。

五、Boot阶段命令

Boot固定115200 bps，不使用舵机ID。进入Boot后，上位机必须先握手，再依次执行开始、写页、完成。

5.1 握手 CMD=01

方向LENDATA偏移字段说明
请求0——无数据
成功应答60STATUS固定0
1升级状态0空白；1升级未完成；2升级完成；3状态页损坏
2～5硬件身份有效时为4项身份；硬件信息页被擦除或无效时为 FF FF FF FF

握手应答不包含Boot版本，也不包含舵机ID或波特率。

5.2 开始升级 CMD=02

方向LENDATA偏移字段类型与要求
请求80～3IMAGE_LENuint32；大于0、256字节对齐、不超过 F400
4～7IMAGE_CRC32对补齐后的完整镜像计算
应答10STATUS0成功；3长度越界；4状态页写入校验失败

执行顺序：

  1. 从有效的参数A页读取ID和波特率；A无效时尝试B页。
  2. 读取硬件身份；若是升级中断后的重试，则优先保留状态页中的已有快照。
  3. 写入并校验IAP状态页，确保身份快照先落盘。
  4. 擦除偏移 0000～F6FF，即APP、A/B参数页和硬件信息页。
  5. 擦除完成后返回成功应答。

未完成升级的有效状态页会在重试时直接复用，不再次擦除。每次设备重新上电后，Boot的RAM状态会丢失，因此即使状态页显示“升级未完成”，上位机仍须重新发送开始命令。

5.3 写入一页 CMD=03

方向LENDATA偏移字段类型与要求
请求2600～3OFFSETuint32；256字节对齐，且小于IMAGE_LEN
4～259PAGE_DATA固定256字节
应答50STATUS0成功；3偏移越界；4读回校验失败；6尚未成功开始
1～4OFFSET原样返回请求偏移，用于匹配应答

Boot对目标页执行“擦除→写入→逐字节读回比较”。同一页可重复发送，页顺序不限。推荐按偏移从0递增写入，且每页收到状态0并确认返回偏移一致后再写下一页。

5.4 完成升级 CMD=04

方向LENDATA说明
请求0无必须在当前Boot会话成功执行开始命令后发送
应答1STATUS0成功；2固件类型不符；4完成标记校验失败；5整包CRC错误；6尚未开始

Boot先对偏移0开始的IMAGE_LEN字节计算整包CRC32，再检查偏移 0100 的固件信息块与硬件快照是否兼容。全部通过后写入完成标记、发送成功应答并复位进入APP。

六、状态码与静默规则

状态码含义上位机处理
0成功继续下一步
1帧、CRC、命令或LEN错误检查组帧；Boot升级循环中可重发
2硬件身份或固件类型不匹配停止升级，选择正确机型固件
3镜像长度或写入偏移越界修正IMAGE_LEN、页对齐或OFFSET
4Flash写入后读回不一致重发当前命令；持续失败时检查供电与Flash
5完整镜像CRC32不一致重新发送全部页面或缺失页面，再发送完成
6顺序错误，当前Boot会话尚未成功开始重新发送开始命令
场景设备行为
APP阶段：错误CRC、错误ID、错误LEN、未知命令静默，不应答
Boot正常升级循环：错误CRC、错误LEN、未知命令返回状态1
Boot上电200ms握手窗口：非握手命令或坏帧静默，不延长窗口
收到CMD最高位为1的帧视为其他设备应答，不处理

七、固件文件与信息块

7.1 Intel HEX处理

  1. 读取Intel HEX记录，校验每行校验和。支持数据记录00、结束记录01、扩展段地址02、扩展线性地址04。
  2. 地址大于等于 08000000 时减去该基地址，得到APP内偏移。
  3. 最高有效偏移必须小于 F400；参数区和状态页不能出现在升级镜像中。
  4. 未出现的地址填 FF。
  5. 从偏移0到最高数据地址，向上补齐到256字节整数页，所得长度为IMAGE_LEN。
  6. 对补齐后的全部IMAGE_LEN字节计算IMAGE_CRC32。

当前官方脚本接收Intel HEX，不直接接收BIN。IMAGE_LEN最大为 0xF400（62464字节）。

7.2 固件信息块

APP镜像偏移 0100 固定放置16字节固件信息块：

偏移长度字段说明
0～34MAGICASCII SVFW
41舵机类型FF 表示不限
51硬件版本FF 表示不限
61电压型号FF 表示不限
71扭矩型号FF 表示不限
8～103固件版本主版本、次版本、修订版本
11～155保留固定 FF

上位机在写入前应检查MAGIC，并使用以下规则核对目标固件：设备硬件身份有效时，固件4项中的每一项必须等于设备值或为 FF。Boot在完成阶段再次执行同样核对。设备硬件身份为 FF FF FF FF 时无法自动判断机型，应由生产流程保证固件正确。

系统只记录一个固件版本：信息块中的主、次、修订版本。协议本身没有版本字段，参数页也没有独立的协议版本或结构版本。

  1. 解析HEX、校验行校验和、生成256字节对齐镜像；读取 0100 信息块。
  2. 按用户提供的当前ID和APP波特率发送查询命令。
  3. 保存查询返回的实际ID、硬件身份和当前固件版本；用硬件身份核对目标固件。
  4. 将查询得到的8字节设备信息原样组成进入升级请求。
  5. 收到成功应答后立即把串口切换为115200，并循环发送Boot握手。
  6. 发送开始命令，等待擦除结束的成功应答。
  7. 从OFFSET=0开始逐页发送。每页收到状态0且返回OFFSET一致才进入下一页。
  8. 发送完成命令。收到状态0或应答超时后等待APP启动。
  9. 切回升级前APP波特率，使用升级前ID查询。读取到的固件版本必须等于目标信息块中的版本。

如果APP查询失败，上位机可切换到115200尝试Boot握手。握手成功说明设备已经停在Boot，可直接从开始命令重新升级。

9.1 救砖流程

  1. 总线上只保留目标舵机。
  2. 上位机打开115200串口并连续发送握手帧。
  3. 提示用户断电后重新上电。Boot在上电后的200ms窗口内只接受握手。
  4. 握手成功后执行开始、写页、完成。

若APP区无效、升级状态未完成或状态页损坏，Boot不会跳入APP，会停留等待升级。

APP接收半帧超过10ms没有新字节会丢弃；Boot接收半帧字节间隔超过50ms会丢弃。主机应一次写出完整帧，不应逐字节长延时发送。

Boot尚未开始升级、且已有可启动APP时，升级循环空闲10秒后自动返回APP；升级未完成时不会因空闲超时进入残缺APP。

十三、上位机参考代码

import struct, zlib

HEAD = b"\xAA\x55"
TAIL = b"\x55\xAA"

def crc32(data: bytes) -> int:
    return zlib.crc32(data) & 0xFFFFFFFF

def build_frame(cmd: int, data: bytes = b"") -> bytes:
    body = bytes([cmd]) + struct.pack("<H", len(data)) + data
    return HEAD + body + struct.pack("<I", crc32(body)) + TAIL

def parse_frame(frame: bytes, request_cmd: int):
    if len(frame) < 12 or frame[:2] != HEAD:
        raise ValueError("frame head/length")
    cmd = frame[2]
    length = struct.unpack_from("<H", frame, 3)[0]
    if len(frame) != 11 + length or frame[-2:] != TAIL:
        raise ValueError("frame boundary")
    body = frame[2:5 + length]
    received_crc = struct.unpack_from("<I", frame, 5 + length)[0]
    if received_crc != crc32(body):
        raise ValueError("frame crc")
    if cmd != (request_cmd | 0x80) or length < 1:
        raise ValueError("unexpected reply")
    status = frame[5]
    return status, frame[6:5 + length]

def start_data(image: bytes) -> bytes:
    assert image and len(image) % 256 == 0 and len(image) <= 0xF400
    return struct.pack("<II", len(image), crc32(image))

def page_data(offset: int, page: bytes) -> bytes:
    assert offset % 256 == 0 and len(page) == 256
    return struct.pack("<I", offset) + page

串口适配器可能回显主机自己发送的请求。解析器应忽略CMD最高位为0的回显帧、其他命令的应答以及CRC错误帧，继续等待当前请求的对应应答。

十四、上位机验收清单

  • 能够在APP当前波特率下按ID查询，并支持单机广播查询。
  • 进入升级时原样回传查询得到的硬件身份和当前固件版本。
  • 进入Boot后切换到固定115200，不再发送舵机ID。
  • 正确实现小端LEN、OFFSET、CRC32和IMAGE_LEN。
  • HEX镜像以FF填洞并补齐256字节，拒绝任何偏移达到F400的数据。
  • 写入前检查偏移0100的SVFW信息块并核对目标硬件。
  • 每页应答同时检查状态码和返回偏移；超时重发同一页。
  • 升级中断后重新发送开始，并从第0页重写，不尝试直接完成。
  • 完成命令超时后仍执行APP版本查询，避免把成功复位误判为失败。
  • 最终在升级前保留的ID和波特率下查询到目标固件版本，才判定升级成功。
