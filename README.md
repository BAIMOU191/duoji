# 舵机固件项目交接文档

本项目是基于 CH32V00X 系列 MCU 的串口舵机固件：支持总线串口 / PWM 脉宽两种输入，位置（90°/180°/270°/360°/自定义行程）、电机定圈/定时等模式，带完整参数表、保护功能、WS2812 状态灯，以及 AES 加密的 IAP 在线升级体系。

文档分两部分：

- **第一部分 代码架构**——快速了解工程框架与控制链路，便于接手代码；
- **第二部分 使用流程**——标定、烧录、升级、换板/换舵机等完整操作手册，按场景给出清单。

配套资料：

| 文件 | 内容 |
|---|---|
| `舵机参数表_电位器版.docx` / `舵机参数表_磁编码版.docx` | 对外参数表（寄存器地址、单位、范围），给使用者查 |
| `IAP升级协议与流程.html` | IAP 升级协议的详细定义（帧格式、命令、状态码） |
| `boot_key.txt` | 升级加密密钥，**务必备份，丢失后已出货舵机无法再升级** |

# 第一部分 代码架构

## 1. 工程总览

| 目录 | 说明 |
|---|---|
| `CH32V00X_APP_ADC` | **电位器反馈版**量产固件（ADC 采样电位器），型号 T1/T3 系列 |
| `CH32V00X_APP_IIC` | **磁编码反馈版**量产固件（MT6701，I2C），型号 T2/T4 系列 |
| `CH32V00X_APP_ADC_TEST` | 电位器**硬件测试/标定辅助固件**：不驱动电机、不跑控制与保护，只每 50ms 打印电位器原始值 `pot:NNNN`；型号为"不限"，可刷到任意样机做硬件检测、给电位器单台标定读端点值 |
| `CH32V00X_IAP` | **Boot 引导**：上电跳转 APP、加密升级、硬件信息页/启动状态管理 |
| `fw_pack.py` | 把 APP hex 打包成加密升级文件 `*_upgrade.bin`（只在出固件的电脑上用） |
| `gen_key.py` | 生成升级加密密钥（AES-128）写入 `boot_key.txt` |
| `iap_upgrade.py` | 串口升级工具（只传输，不接触密钥），也做查询和救砖 |

两个 APP 工程（电位器/磁编码）结构完全相同、大部分源码逐字节一致，**差异只在三处**：

1. `Application/App_Model.h`——型号表（电机标定、编码器常量、工作电压）；
2. `Application/A_Sensor.*`——编码器读取与几何（电位器有死区与开环脱困，磁编码整圈绝对角度、无死区）；
3. `Drivers/`——磁编码版多 `D_mt6701`/`D_i2c`，电位器版走 ADC 滤波。

## 2. APP 固件分层与模块职责

```
User         main.c（初始化顺序）、中断 ch32v00X_it.c、链接脚本 SRC/Ld/Link.ld
  ↓
Application  业务层 A_*：配置/参数表/协议/舵机编排与执行/保护/状态灯/标定
  ↓
Common       纯算法 C_*：轨迹规划、观测器、位置控制、电机模型、调度器、定点库
  ↓
Drivers      板级驱动 D_*：UART / Motor(H桥) / TIM / ADC / OPA / I2C / SPI
             / WS2812 / TMP112 / MT6701 / IWDG
  ↓
SRC          WCH 官方标准库（core_riscv、ch32v00X_* 外设库），不改
System       ch32v00X_conf.h、flash.c（参数页读写）、iap.c（升级服务+硬件信息）
```

| 模块 | 职责 |
|---|---|
| `A_Config` | 固件常量与掉电保存参数（Flash/SRAM 双份）；上电修复非法字段、异步落盘 |
| `App_Model.h` | **随型号变化的全部数据**：型号选择、编码器常量、四参数、电机标定、电压范围 |
| `A_Param` | 虚拟寄存器参数表（地址 0x00~0xFF）：范围校验、写后联动；二进制协议的后端 |
| `A_UartCmd` | 串口协议层：明文帧 / 二进制帧 / 升级帧按帧头独占分流 |
| `A_Servo` | 舵机编排层：输入源检测、指令受理与合并、扭矩/暂停/停止/堵转、上电动作、1ms 控制拍 |
| `A_Servo_Ctrl` | 执行层：坐标与校准、算法链装配、输出级（mV↔占空比、限幅、阻尼、卸力） |
| `A_Sensor` | 传感器聚合：编码器/电压/温度/电流 → 业务单位（厘度、mV、0.1℃、mA） |
| `A_Protect` | 保护（过温/过流/堵转/电压）与扭矩限流 |
| `A_StatusLed` | WS2812 状态灯 |
| `A_Debug` | VOFA+ FireWater 诊断输出（默认关，可用编译宏打开） |
| `A_Calib_Min` | 开环电机标定固件（`APP_MODE_CALIB` 编译开关，见第二部分 §4） |
| `C_Traj_Planner` | 在线 S 曲线轨迹规划：V/A/D 限幅、平滑时间、最短运动时间 |
| `C_Speed_Observer` | 三状态模型观测器：位置/速度/扰动电压估计 |
| `C_Pos_Ctrl` | 位置控制器：MOVE→SETTLE→HOLD 三态，模型前馈+P+积分+扰动前馈 |
| `C_Motor_Model` | 电压域电机模型 U = kv·ω + ka·α + fc·sgn(ω)（标定的理论模型） |
| `C_Task_Scheduler` | 协作式优先级任务调度器（1ms 时基，不抢占） |
| `C_Ring_Buf` / `C_Fixed` | 环形缓冲、定点数/倒数乘法工具 |

**接手代码的推荐阅读顺序**：`User/main.c`（初始化顺序）→ `A_Tasks.c`（任务表）→ `A_Servo.c`（1ms 控制拍）→ `A_Servo_Ctrl.c`（算法链装配）→ `Common/C_*`（纯算法）。

## 3. 控制链路

### 3.1 任务调度

主循环每轮跑一个最高优先级就绪任务，不抢占（`A_Tasks.c`）：

| 优先级 | 周期 | 任务 | 内容 |
|---|---|---|---|
| 0 | 1ms | ServoControl | 1ms 控制拍（见下） |
| 1 | 1ms | Uart | 串口收帧执行 + IAP 升级服务 |
| 2 | 10ms | Protect | 电压/电流/温度采样、保护判定 |
| 3 | 20ms | State | 状态灯 + 喂狗（卡死则看门狗复位） |
| 4 | 20ms | ConfigSave | 参数变脏时写 Flash（运动中顺延，最多顺延 500ms） |
| 5 | 20ms | Print | VOFA+ 诊断输出（默认关） |

### 3.2 1ms 控制拍（核心链路）

```
输入受理（串口指令合并 / PWM 脉宽捕获——PA1 与 PC0 共线，上电自动二选一）
   → 读编码器（A_Sensor，换算为厘度）
   → 观测器（C_Speed_Observer：位置/速度/扰动电压）
   → 轨迹推进（C_Traj_Planner：参考位置/速度/加速度，新指令随时覆盖旧的）
   → 位置控制（C_Pos_Ctrl：前馈 + P + 积分 + 扰动前馈 → 电压 mV）
   → 输出级（mV → 占空比，按实测母线电压换算；限幅/阻尼/卸力）
   → H 桥（D_motor，TIM 20kHz PWM，AT8236）
```

- **指令链**：串口/PWM → `A_Servo_Submit`（脉宽+时间）→ `C_Traj_Command` → 逐拍跟踪 → 到位判定（到位窗=保持窗）。
- **保护链**：10ms 采样 → 故障/堵转判定 → 扭矩限流、PWM 上限、停机卸力、堵转就地保持。
- **参数链**：协议 → `A_Param` 表（校验+联动）→ `g_config`/`g_runtime_config` → MarkDirty → ConfigSave 任务异步落盘（指令路径不写 Flash）。

### 3.3 位置控制器

三态（`C_Pos_Ctrl.h`）：MOVE（运动：模型前馈+P/速度反馈+积分）→ SETTLE（收尾：无记忆 P+阻尼）→ HOLD（保持：对超出到位窗的误差做 PI）。积分分账：运动中的动态份额停下后渐撤，静载（重力）留下；支持负载惯量比前馈与位置负载自学习。

## 4. Flash 分区与固件兼容机制

| 区域 | 地址 | 说明 |
|---|---|---|
| Boot | 0x0000~0x13FF（5KB） | IAP 引导，升级时不改写 |
| APP | 0x1400~0xF3FF（56KB） | 应用固件；偏移 0x100 处是固件信息块 `SVFW` |
| 参数页 A/B | 0xF400 / 0xF500 | 掉电保存参数（双页备份），含舵机 ID、波特率 |
| 硬件信息页 | 0xF600 | 硬件身份 4 字节 + 运动规格（APP 上电时建立/更新） |
| 启动标志页 | 0xF700 | Boot 维护的升级状态（UPGD/APOK） |

**型号机制（升级校验的基础）**：

- 型号宏名 = `T{舵机类型}_H{硬件版本}_V{电压型号}_Q{扭力型号}`，如 `T4_H10_V8_Q15` = 类型4、硬件 v1.0、8V、15kg。四个参数写入固件信息块，升级时与舵机硬件信息页比对（固件侧 0xFF = 不限）。当前型号表：
  - 电位器版（`CH32V00X_APP_ADC\App_Model.h`）：T1_H10_V8_Q15/Q20/Q30、T1_H10_V12_Q35、T3_H10_V8_Q15；
  - 磁编码版（`CH32V00X_APP_IIC\App_Model.h`）：T2_H10_V8_Q20、T4_H10_V8_Q15。
- 硬件信息页由 **APP** 上电时写入（`IAP_Init()`），Boot 只读不写。首次刷入某型号固件后，这块板子的"型号身份"即被固定。
- `image_tag`（APP 镜像指纹）：换固件后参数整体回默认，**仅保留舵机 ID 和波特率**（IAP 升级同样只保留这两项）。

## 5. 对外协议（概览）

一根 TTL 单线半双工（USART1，PC0；发送期间关接收，主机必须等应答发完再发下一条），三种帧按帧头独占分流：

| 帧 | 格式 | 用途 |
|---|---|---|
| 明文 | `#<ID三位>P<指令>!` | 运动、查询、校准、设置（见第二部分速查表） |
| 二进制 | `AA 66 ID CMD LEN DATA CRC8 66 AA` | 参数表读写（CMD 02/03）、状态查询（01）、恢复出厂（07/08） |
| 升级 | `AA 55 CMD LEN DATA CRC32 55 AA` | IAP 升级（0x01 握手 / 0x02 开始 / 0x03 写页 / 0x04 完成；APP 侧 0x20 查询 / 0x21 进入升级） |

- ID 255 为广播：全体执行，应答延迟 100ms + 本机ID×2ms 错开；**广播禁止改 ID / 全部恢复出厂**。
- 参数地址分区：`00~0F` 硬件信息（只读）、`10~1F` 固件（只读）、`20~4F` Flash 参数（掉电保存）、`80~BF` SRAM 参数与动作、`C0~` 只读实时状态。完整地址表见参数表 docx 与第二部分 §7。
- 输入源：PA1（PWM 捕获）与 PC0（串口）是同一根信号线，上电 60ms 嗅探到 PWM 即按 PWM 输入工作，否则按串口总线。

# 第二部分 使用与操作流程

## 0. 环境与工具准备

| 工具 | 用途 |
|---|---|
| MounRiver Studio | 编译 4 个固件工程；自带 **WCH-LinkUtility**（Tools 菜单）用于下载/擦除芯片 |
| Python 3 | 运行三个脚本；`iap_upgrade.py` 需要 `pip install pyserial` |
| 串口工具 / 上位机 | 半双工单线 TTL，默认 115200（档位 5） |
| USB 转 TTL + 供电电源 | 半双工单线接线；供电按型号：8V 型工作 6.0~9.0V、12V 型 9.0~13.0V（见型号表） |

**密钥管理（重要）**：

- `gen_key.py` 生成 16 字符密钥写入 `boot_key.txt`；把这串字符**原样**粘贴到 `CH32V00X_IAP/System/boot_key.h` 的引号里，重新编译 Boot。`fw_pack.py` 打包时读同一个 txt，两边必须一致，否则 Boot 会因整包 CRC 不符拒绝升级。
- `boot_key.txt` **务必备份**到安全的地方。密钥丢失 = 已出货舵机永远无法再升级。
- 换密钥后，烧着旧 Boot 的舵机将无法升级；`gen_key.py` 默认拒绝覆盖已有密钥（要换需 `--force`）。

## 1. 全新板子（空白芯片）：从零到可用

1. **编译 Boot**：MounRiver 打开 `CH32V00X_IAP`，编译得到 `CH32V00X_IAP\obj\CH32V00X_IAP.hex`。
   - 确认 `System/boot_key.h` 里的密钥与 `boot_key.txt` 一致；
   - 确认 `System/boot_config.h` 的 `BOOT_RDP_ENABLE`：**量产时置 1**（上电自动开读保护），**开发时可置 0**（当前仓库是 0）。开发板不要烧量产版：读保护开启后 WCH-Link 无法再下载 APP，只能用 WCH-LinkUtility 解除读保护（整片擦除）。
2. **下载 Boot**：WCH-LinkUtility 下载 `CH32V00X_IAP.hex`。**不需要手动开读保护**——量产版 Boot 上电自检时会自动开启（断电再上电后生效），烧录时保持未保护状态才方便下载。
3. **选择/切换舵机型号**（见 §2），编译 APP 工程，`python fw_pack.py` 打包加密固件（见 §3）。
4. **首次升级**：`python iap_upgrade.py` 或上位机刷入 `*_upgrade.bin`。此时舵机硬件信息页空白，**任意型号固件都可刷入**；刷入后 APP 首次上电把本固件的四参数写入硬件信息页，型号身份从此固定。
5. **现场校准**（见 §6）并设置 ID、波特率。

> 首次升级之后，升级工具会校验固件适用硬件与板子是否一致，**不一致拒绝升级**。想给已固定的板子换型号固件，只能用 WCH-LinkUtility 整片擦除（Boot 也会被擦掉），重新走 1~4。

## 2. 选择/切换舵机型号

1. 打开对应工程的 `Application\App_Model.h`，顶部 `#define APP_MODEL APP_MODEL_xxx` 选中目标型号（每次只启用一个）。
2. **新型号**（新电机/新减速箱/新结构/新电压档）：在型号表里新建一整节，命名规则 `T{舵机类型}_H{硬件版本}_V{电压型号}_Q{扭力型号}`，填入四参数（`FW_SERVO_TYPE/FW_HW_VERSION/FW_VOLTAGE/FW_TORQUE`）、电机标定、工作电压范围。
3. 固件版本号在 `A_Config.h` 第 1 节（`SERVO_VERSION_MAJOR/MINOR/PATCH`），发布新版固件时记得递增，升级时会与舵机当前版本比对提示。
4. 编译 → 打包 → 升级（§3）。

## 3. 编译、打包与升级

### 3.1 打包（出固件的电脑上做，打包产物才发出去）

```bash
# 默认打包配置里的 hex 和密钥（脚本开头 HEX_FILE/KEY_FILE 两行）
python fw_pack.py

# 或命令行指定
python fw_pack.py 路径\app.hex 路径\boot_key.txt
python fw_pack.py --hex app.hex --key boot_key.txt --out xxx.bin
```

- 产物：与 hex 同名的 `*_upgrade.bin`（AES-128-CTR 加密 + 校验头）。
- 注意脚本开头 `HEX_FILE` 默认指向 `CH32V00X_APP_IIC\obj\CH32V00X_APP.hex`，打包电位器版固件时改成 `CH32V00X_APP_ADC\obj\CH32V00X_APP.hex` 或用命令行传入。
- 密文固件里不出现明文代码；上位机/升级工具不需要密钥，**不要把密钥发给客户**。

### 3.2 升级

```bash
python iap_upgrade.py --query                      # 只读舵机信息（ID/型号/版本），不升级
python iap_upgrade.py --port COM5 --id 3           # 按脚本配置升级
python iap_upgrade.py --port COM5 --id 3 --fw xxx_upgrade.bin
python iap_upgrade.py --rescue                     # 救砖：提示断电重上电后再升级
```

升级流程（脚本自动完成）：查询型号 → 型号比对 → 进入升级（APP 复位进 Boot）→ 握手 → 开始（擦除）→ 逐页写入（解密+写后读回）→ 整包 CRC 校验 → 跳新 APP → 查询版本确认。

要点：

- **升级保留舵机 ID 和波特率**，其余配置用新固件默认值。
- 一条总线上**建议只接一台**升级（固件里可能存在会被其他舵机误认的字节序列，脚本会自动提示）。
- 升级中途断电可直接重跑脚本：舵机会停留在 Boot 里（脚本会自动识别"已在 Boot"并继续）；重发从第 0 页开始，无断点续传。
- Boot 固定 115200 通信（与舵机当前波特率无关），升级时不需要改串口波特率设置。

### 3.3 升级失败状态码

| 状态 | 含义 | 处理 |
|---|---|---|
| 1 | 帧无效（长度不对） | 检查串口丢包/接线 |
| 2 | 硬件信息或固件类型不符 | 固件型号与板子不匹配；换对应型号固件，或整片擦除重来（§1） |
| 3 | 地址或长度越界 | 换新打包的固件 |
| 4 | 写入后读回不一致 | 重试；反复失败换板 |
| 5 | 整包 CRC 不符 | 固件文件损坏或密钥与 Boot 不一致，重新打包/核对密钥 |
| 6 | 顺序错误（尚未成功开始） | 重新运行脚本 |

## 4. 电机标定（换电机 / 减速箱 / 新机型必做）

电机标定用开环标定固件实测辨识电压域模型 `U = kv·ω + ka·α + fc·sgn(ω)`，打印一段可直接粘贴的 C 代码块。**同一型号的所有舵机共用同一份标定值**（写在 `App_Model.h` 型号表里），只在换电机、换减速箱或新型号时重做。

### 4.1 步骤

1. **开标定固件**：取消注释 `User\main.c` 里的 `// #define APP_MODE_CALIB`，编译、升级（或下载）到舵机。此时舵机不跑控制与保护，只做标定。
2. **物理准备**：
   - 输出轴**空载自由转动**（不装摇臂/连杆/负载）；
   - 供电用**额定电压**（8V 型号 ≈8V，电源要能承受满占空比阶跃与反接制动的冲击电流）；
   - 行程两端留出保护余量（磁编码版工作扇区 0~270°，阶跃段最长跑 180°，勿撞限位）；标定全程约 **3~4 分钟，期间勿碰输出轴**。
3. **观察串口**（默认 115200）：开机打印 `CALIB start x.xxV，约3~4分钟…`，随后 `@SEG,n/59,noise|ramp|step|pulse` 逐段进度，结束打印**电机标定块**和 `@DONE`。
4. **复制标定块**：从 `/* ---- 电机标定（标定固件打印，整节替换 App_Model.h 对应型号块） ----` 到 `/* ---- 电机标定结束 ---- */`，**整节替换** `App_Model.h` 中当前型号的电机标定区。
   - 若标定块内出现 `#error "标定自检未通过：…"` 并伴随 `@WARN,...`：说明数据可疑（见 4.3），**不要直接采用**，排查后重标。
5. **恢复正常固件**：把main.c的 `APP_MODE_CALIB` 重新注释掉，重新编译打包，升级回正常固件（标定固件也保留 IAP 通道，可直接用 `iap_upgrade.py` 刷回）。
注：电位器电机，若标定时输出轴处于电位器死区可能无法正常标定，需要手动把输出轴掰到有效区在上电

### 4.2 标定块字段（12 项）

`MOTOR_CAL_MV`（标定电压）、`MOTOR_KV_UV`（反电势斜率）、`MOTOR_KA_NV`（加速系数）、`MOTOR_FC_MV`（动摩擦）、`MOTOR_FS_MV`（起转电压）、`MOTOR_DELAY_US`（纯延迟）、`MOTOR_NOISE_CDEG`（静止噪声）、`MOTOR_MIN_STEP_CDEG`（最小可靠位移）、`MOTOR_SIGN`（旋向）、`MOTOR_RATED_VEL_DPS`/`MOTOR_RATED_ACC_DPS2`/`MOTOR_RATED_DEC_DPS2`（额定速度/加速度/减速度，已留 10% 余量）。

### 4.3 失败与自检

| @FAIL 码 | 含义 | 排查 |
|---|---|---|
| 2 | 试推 200ms 位移 <0.5° | 电机没转：接线、供电、驱动 |
| 3 | 编码器读数失败 | 编码器接线/器件 |
| 4 | 越出工作扇区保护带 | 输出轴被限位挡住或被人转动 |
| 5 | 预定位 8s 超时 | 卡滞、极性异常 |
| 6 | 起转点 <4 个或最小位移测不出 | 摩擦异常、打滑 |
| 7 | kv/fc 或 τ/延迟拟合失败 | 有效数据点不足，重标 |

自检不过（块内 `#error` + `@WARN`）的常见原因：τ 不在 10~80ms（卡滞/打滑）、两向 kv 差 >10%（机构单边受力）、起转电压 ≤ 动摩擦、延迟贴 8ms 搜索上限、制动出力比超 0.3~2.5、最小可靠位移 >0.8°（齿隙过大）。

## 5. 电位器版单台标定（换电位器 / 新装配必做）

电位器个体差异大，每个型号表里有一节"**电位器标定（单台实测，整节替换）**"：`ENCODER_POT_ADC_MIN`（0° 端 ADC 计数）、`ENCODER_POT_ADC_MAX`（满行程端 ADC 计数）、`ENCODER_POT_SPAN_CDEG`（标称行程，一般 27000 不变）。**每台舵机装配后都要实测这两个端点值。**

1. 编译 `CH32V00X_APP_ADC_TEST`（测试固件：不驱动电机、可手转输出轴，型号"不限"可刷任意样机），升级或下载到舵机。
2. 串口 115200 观察每 50ms 一帧的 `pot:NNNN`（0~4095 的电位器原始计数）。
3. 手转输出轴到行程一端，读数稳定后记为 `ENCODER_POT_ADC_MIN`；转到另一端记为 `ENCODER_POT_ADC_MAX`。
4. 把两个值填进量产工程 `App_Model.h` 对应型号的电位器标定区，重新编译量产固件、打包、升级。
5. 磁编码版（MT6701 绝对角度）**不需要**此步骤。

> 抽头接触不良的表现：反复"开环脱困"（电位器掉入死区时固件会低速开环转出死区），最终报编码器故障停机卸力。换电位器或改动装配后必须重测端点。

## 6. 装机现场校准与常用指令

装机（摇臂/连杆装好）后，用串口指令做一次现场校准。校准在 Flash 里只存"锚点"，有效行程与零点由锚点+模式标称行程现推，**反复校准不叠加**。

### 6.1 明文指令速查（`#<ID三位>P<内容>!`）

**运动**（受理后不回复；失败也不回复，可用查询确认）：

| 指令 | 含义 |
|---|---|
| `#001P1500T1000!` | 走到 1500us 对应位置，用时 1000ms（`T0000`=最快；时间是 4 位，电机定圈模式时为圈数） |
| `#001P1500N2T1000!` | 多圈：走到 1500us 位置、转 2 圈、每圈 1000ms（**仅磁编码版**） |

**查询**：

| 指令 | 回复 |
|---|---|
| `#001VER!` | `#001PServo-V1.0.0!` 固件版本 |
| `#001RAD!` | `#001P1500!` 当前位置（us） |
| `#001RIV!` | `#001PI0103V7.0!` 电流(mA，±4位)+电压 |
| `#001RTV!` | `#001PDP1500T25V7.0!` 位置+温度+电压 |
| `#001MOD!` / `#001BD!` / `#001SP!` / `#001CSM!` | 工作模式 / 波特率 / 扭矩上限 / 上电动作 |
| `#001ID!` | `#001P!` 本机 ID |

**设置**（成功回 `#001POK!`；越界整条不认）：

| 指令 | 含义 |
|---|---|
| `#001ID002!` | 改 ID 为 2（0~254；**广播不能改 ID**） |
| `#001BD5!` | 波特率档 1~8（1=9600 2=19200 3=38400 4=57600 **5=115200 默认** 6=128000 7=256000 8=1000000；应答发完才切换） |
| `#001MOD5!` | 工作模式（1/2=270° CW/CCW，3/4=180°，5/6=90°，7/8=360°（仅磁编码），9~12=定圈/定时电机模式，13=自定义行程只能由 AMI/AMX 进入） |
| `#001SP080!` | 扭矩上限 80%（0=禁止主动驱动，100=额定堵转电流） |
| `#001CSM1!` | 上电动作：1=转到上电位置，2=保持当前位置，3=小阻力释放（首条指令恢复） |

**运动控制**：

| 指令 | 含义 |
|---|---|
| `#001DPT!` / `#001DCT!` / `#001DST!` | 暂停（保持暂停点）/ 继续 / 停止（按减速度刹停，不回复） |
| `#001ULK!` | 卸力自由转 |
| `#001ULM!` | 短路阻尼卸力 |
| `#001ULR!` | 恢复力矩 |

**校准**（成功回 `#001POK!`）：

| 指令 | 含义 |
|---|---|
| `#001SCK!` | **当前角度标为行程中点**（1500us 对应角度）——最常用 |
| `#001SCZ!` | 当前角度标为行程起点（500us 端） |
| `#001AMI!` / `#001AMX!` | 当前位置设为自定义行程的起点/终点（随后模式进 13） |
| `#001SMI!` / `#001SMX!` | 当前位置的脉宽设为可响应的下/上边界（限制后续运动指令范围） |
| `#001CSD!` | 当前位置保存为上电目标（配 CSM1 使用） |
| `#001CLE0!` | 恢复出厂（**保留 ID**；波特率回默认 115200） |
| `#001CLE!` | 全部恢复出厂（ID 也清零；**广播不允许发**） |

### 6.2 典型校准流程

1. 装好摇臂，上电，发 `#001ULK!` 卸力，手动把输出轴放到机械行程中点；
2. 发 `#001SCK!`（或把轴放到行程起点发 `#001SCZ!`）；
3. 需要限制响应范围时再发 `#001SMI!`/`#001SMX!`（把轴转到边界位置执行）；
4. 需要特定上电姿态：把轴摆到位 → `#001CSD!` → `#001CSM1!`；
5. 发运动指令验证往返是否对称、端点是否到位。

## 7. 二进制协议与参数表（上位机用）

帧：`AA 66 ID CMD LEN DATA CRC8 66 AA`（CRC8/ATM，多项式 0x07）。命令：`01` 状态查询、`02` 读参数、`03` 写参数、`07` 恢复出厂（保留 ID）、`08` 全部恢复出厂。应答帧 CMD|0x80，DATA[0] 为状态码（0 成功 / 1 命令不存在 / 2 长度错 / 3 值非法 / 4 状态不允许 / 5 执行失败 / 6 只读 / 7 不支持）。

常用参数地址（完整表见参数表 docx）：

| 地址 | 含义 | 地址 | 含义 |
|---|---|---|---|
| 00~03 | 舵机类型/硬件版本/电压/扭力 | 20/21 | ID / 波特率档 |
| 04~08 | 额定 V/A/D、平滑 τ、最小位移 | 22/23 | 工作模式 / 上电动作 |
| 10 | 固件版本（3B） | 24/25 | 扭矩上限% / 上电位置码(0~4095) |
| 80 | 运动请求（只写：位置码 2B+时间 2B） | 30~34 | Vmax/Amax/Dmax/平滑/最短运动时间 |
| 81 | 运动动作（1 继续 2 暂停 3 停止） | 35/37/38 | 保持 P / 到位精度 / 保持 I |
| 82/83 | 扭矩模式 / 阻尼%（SRAM，掉电恢复默认） | 40~45 | 过流/过温/堵转保护参数 |
| 8B/8C | 标定动作（1=SCK…7=CSD）/ 系统动作 | 46~4B | 保护开关、工作电压、启动扭矩、负载惯量、自学习 |
| C0~C9 | 实时状态：工作状态/故障/位置/速度/温度/电压/电流/扭矩/堵转/集合查询 | | |

写入规则：`20~4F` 立即生效且掉电保存（写 Flash 异步完成，运动中顺延）；`80~9F` 立即生效**不保存**；位置码 0~4095 对应 500~2500us。

## 8. 状态灯（WS2812）含义

| 灯效 | 含义 |
|---|---|
| 彩虹循环（约 6.1s 一轮） | 正常：空闲 / 运动 / 脱困恢复 |
| 蓝常亮 | 暂停 / 卸力（自由或阻尼释放） |
| 橙常亮 | 过温（先查负载与散热） |
| 紫常亮 | 过流 |
| 红慢闪 | 电源异常（过压/欠压/电压采样无效） |
| 绿慢闪 | 设备异常（故障态） |

## 9. 常见场景操作清单

| 场景 | 要做什么 |
|---|---|
| **新板子（空白芯片）** | 烧 Boot（§1）→ 选型号 → 编译打包 → 首次升级 → 现场校准 + 设 ID |
| **同型号整机更换** | 装机现场校准（§6）+ 设 ID/波特率即可；电机标定随型号共用，不用重做。**电位器版**还要做单台电位器标定（§5）并重刷固件 |
| **换电机 / 减速箱** | 重新电机标定（§4）→ 整节替换 `App_Model.h` → 重编译打包 → 升级 |
| **换电位器 / 改装配（电位器版）** | 重测单台电位器标定（§5）→ 替换 → 重编译打包 → 升级 |
| **换板子（硬件改版）** | 核对 `A_Config.h` 第 2 节板级常量（分压比、采样电阻、PWM 分辨率等）；新建型号节（硬件版本号递增）；重做电机标定（+电位器版单台标定）；Boot 不用改 |
| **给已固定型号的板子换型号固件** | 升级会被拒绝；用 WCH-LinkUtility 整片擦除（Boot 一起擦掉），重新走"新板子"全流程 |
| **同型号固件升级（日常）** | `fw_pack.py` 打包 → `iap_upgrade.py` 升级；ID/波特率保留，其余参数回默认 |
| **固件刷坏了（救砖）** | `python iap_upgrade.py --rescue`，按提示断电重上电后继续升级 |

## 10. 常见问题排查

**查不到舵机 / 无应答：**

1. "不回"不等于"不在"：运动指令、`DST`、失败的设置按协议本来就不回复；坏帧、别人 ID 的帧一律静默。
2. 文本帧格式必须严格 `#<ID三位>P...!`；帧内字节间隔 <10ms（半帧 10ms 超时丢弃）。
3. 波特率要匹配（出厂 115200）；改过波特率的舵机要换对应档位重试。
4. 半双工单线：主机必须等应答发完再发下一条；多机广播应答最迟约 100+2×ID ms 才出。
5. 二进制帧注意 CRC8、LEN、帧尾 `66 AA`；CMD 最高位=1 是应答帧会被忽略。
6. 总线上多台同 ID 一起应答会导致读不成帧——升级/排查时只接一台。

**升级相关：** 见 §3.3 状态码表；升级中断后舵机停在 Boot（重跑脚本即可继续）；`--query` 先确认舵机在线和型号。

**参数突然回默认：** 换固件（镜像变化）后参数整体回默认，但 ID/波特率会保留——升级后记得重新下发业务参数。

**标定相关：** 见 §4.3；标定数据被污染（触碰输出轴、限位挡住）通常表现为自检不过，重标即可。
