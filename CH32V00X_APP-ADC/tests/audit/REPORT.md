# 舵机应用代码复审与回归验证

日期：2026-09-09。基线为用户已实机确认效果良好的版本，保存在 `tests/audit/baseline`。本报告区别于上一轮 `tests/sim/REPORT.md`，所有“修改前”均指本轮基线。

## 范围与结论

审查舵机应用、轨迹规划、位置控制、速度观测、保护、配置、协议及相关采样和调度调用关系。实际修改仅涉及 `A_Servo.c`、`A_Protect.c`、`C_Traj_Planner.c`、`C_Pos_Ctrl.c` 四个生产文件。保留现有控制参数，包括到位静音门限、起转门槛、PWM 输入过滤和减速参数。

**IAP 升级源码及相关系统文件未修改。** 先前发现的 IAP 长度校验问题按用户要求排除在本轮修复之外，因此本报告不代表 IAP 已通过安全性审查。

已完成可复现问题修复、原有场景对比、边界回归、随机规划及目标芯片完整编译。测试未发现新增失败；仿真无法证明不存在所有隐藏问题，也不能替代实机时序和机械负载验证。

## 复现与修复

| 问题 | 修改前的复现结果 | 本次处理及验证 |
|---|---|---|
| 高速运动中把目标改到参考位置附近 | 参考速度 27283 厘度/秒时，将目标改为参考位置 +1 厘度，T=0，规划时长达到 57140635ms（约15.9小时） | 小位移限速不能抹掉已有动量对应的制动能力；同例规划 237ms |
| 规划器负数左移 | 未定义行为运行检查在段末位置计算处触发 | 改为等价的有符号宽位乘法，运行检查通过 |
| 脱困期间停止 | 仍继续输出脱困 PWM，且旧的延迟指令仍保留 | 停止挂起脱困并清除延迟目标；直到新运动指令才继续 |
| 脱困期间暂停 | 暂停后仍有驱动 | 暂停判断提前；继续指令恢复脱困，反馈恢复后再规划原目标 |
| 脱困期间卸力后发送新目标 | 延迟指令先返回，无法恢复扭矩，舵机一直留在死区 | 接受新目标前恢复扭矩，再保存脱困后的目标 |
| 中位标定后切换行程 | 180度模式标定后切回270度，目标可超过电位器真实测量范围 | 逻辑行程与真实测量安全范围求交；无有效交集时禁止驱动 |
| 反馈失败时保存上电位置 | 使用旧角度并报告保存成功 | 读位置失败时拒绝保存，保留原设置 |
| 保护期间恢复扭矩 | 恢复指令或运动指令可让电机重新带电，直到下一次保护任务 | 舵机命令入口检查当前保护故障，拒绝恢复和新运动 |
| 零扭矩上限回升 | 设置0%，有效电流读数为零时，上限可逐步升到满 PWM | 零设置保持最小限幅，不参与回升。沿用原接口的最小值1，0仍表示取消限幅；此设置不等同于ULK卸力 |

七组舵机状态测试在基线全部能触发失败，修复后全部通过。零扭矩问题另有独立保护测试。轨迹重置同时刷新参考和饱和诊断，避免下一条指令使用旧状态。

## 冗余与效率整理

- 删除与加速整形完全相同的三份换向整形状态、重复除法和条件选择，直接复用加速整形结果。
- 删除规划器初始化阶段不会被使用的限值预算；静止且目标相同的请求在动力学计算前返回。
- 位置控制每拍只计算一次实际位置残差及其绝对值；在编译期范围约束下，将一处不必要的64位除法换为32位运算。
- 删除保护模块仅供初始化中转的 `pwm_ff` 状态，以及现有上限逻辑不可能进入的下降分支；更新对应注释。

这些整理未改控制增益。未测量芯片上的实际耗时，不能据此宣称控制周期缩短了某个百分比。修复增加的边界判断也有少量指令开销。

## 验证方法与结果

主机仿真直接编译生产版舵机、传感器、规划器、观测器和位置控制代码，只替换硬件接口。保护模块另外使用真实生产代码和可控传感器输入测试，主机械仿真没有模拟真实电流/温度回路。没有执行 IAP 接收处理。

1. **原有回归：** 坐标转换、大角度 `500→2000→500`、T=0 快速换向、PWM 输入抖动、两端死区上电、外力扰动、恒定负载及卸载均通过。正常场景 CSV 完全相同；两端上电 CSV 各仅一拍的诊断参考位置不同，全部电机输出、实物位置和速度相同。
2. **模型散差：** 增益0.7/1/1.3倍、惯性0.7/1/1.3倍、摩擦1/1.5倍、延迟1/4ms，共36种模型，每种4次动作，合计144次。本轮前后结果相同，最大越位2.112462度，最大终点误差0.43236度。这是压力模型结果，不是实机精度保证。
3. **状态边界：** 停止、暂停/继续、卸力后新目标、标定换行程、反馈失败保存、保护拒绝恢复、无有效行程等七组全部通过。
4. **保护回归：** 连续过流判定、单拍/失效采样不累计、冷却时长、过温回差、温度读取失败保持故障、原有用户卸力保留、限流下降、无效电流采样保持上限、非法百分比、零设置及恢复100%全部通过。
5. **随机规划：** 固定种子47，10000次计划，混合T=0与0～65535ms、0～100平滑度、不同位置及运动中改目标，检查位置范围、速度上限和每拍位置跳变，全部通过。
6. **运行时检查：** 真实算法和上述状态/保护/随机规划测试使用 GCC 未定义行为检查的陷阱模式，修复后没有触发。未使用地址消毒器，不把该检查等同于完整内存安全证明。
7. **配置变体：** 反向电机安装、反向位置模式、磁编码器分支的构建与适用回归通过；这些变体只在测试副本中修改参数。
8. **完整固件：** 使用工程所用 WCH RISC-V GCC12 编译全部源文件并链接，成功生成 ELF/HEX/BIN。应用和算法无编译警告；唯一警告为已有厂商 `SRC/Debug/debug.c` 的 `_write` 未使用参数 `fd`。

详细机器结果：`tests/audit/results/state_cases.json`、`tests/audit/results/verification.json`；方向变体结果：`tests/sim/results/variants.json`。复现命令为 `python tests/audit/run_audit.py` 与 `python tests/audit/verify.py`，需要已安装的主机 GCC。
