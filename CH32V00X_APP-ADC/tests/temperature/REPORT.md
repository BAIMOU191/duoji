# 温度一直回复0：代码定位与修复

日期：2026-09-09。用户现象：温度之前正常，目前每次读取均为0，电压正常。未连接实机，以下区分代码中已确认的问题与尚待硬件验证的因果关系。

## 已确认的问题

1. **读取失败被显示成0。** `D_TMP112_Read_Temp` 在I²C失败时返回-32768，`A_Temperature_Read` 原样转发，但串口RTV回复把这个失败值替换为0。因此T0无法区分真实0°C与通信失败。电压通过独立ADC采集，电压正常不能证明I²C正常。
2. **两字节接收的ACK/ADDR顺序错误。** 原驱动先关闭ACK，再清ADDR。CH32V00X参考手册的CTLR1.POS说明要求两字节接收先清ADDR、随后立即清ACK，以对第二字节发NACK。TMP112温度和配置均读取两字节，都会受影响。已按手册修正，保留该短时序段的中断保护。[WCH参考手册，PDF第211页](https://ch32-riscv-ug.github.io/CH32V006/datasheet_en/CH32V00XRM.PDF#page=211)
3. **标称400kHz的分频实际算成480kHz。** 工程PCLK为48MHz；库对16/9占空比计算CCR时，48MHz/(400kHz×25)=4.8被整数截成4，名义SCL成为480kHz。改用2:1占空比，CCR=40，计算结果为400kHz。实际波形频率还受时钟精度影响。此修改消除时序偏差，但没有实机证据说明它是此次故障的主要原因。

温度换算公式本身正确：0x1900对应25.0°C。配置0x60A0表示连续转换、4Hz，原注释误写1Hz，已纠正注释，配置值未改。寄存器格式和转换速率已核对[TI TMP112数据手册](https://www.ti.com/lit/ds/symlink/tmp112.pdf)。
